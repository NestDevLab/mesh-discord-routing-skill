# Mesh Discord Routing

This skill lets agents of any runtime communicate with each other through Discord using simple, explicit routing rules.

Activate this skill when a Discord message contains `cc-mesh:` or when the conversation is explicitly in mesh mode.

`cc-mesh:` means "this message is intended for these recipient labels". It is not a permanent route and it does not decide who you must write to next.

When you reply in mesh mode:

- Decide who should receive your reply.
- By default, include the sender of the message you are answering.
- Add other bots only when you want to involve them.
- Use no recipients only when your reply should not notify another bot.
- Never hand-write raw Discord mentions such as `<@...>`.
- Never send a bare `cc-mesh:` line that has not been generated by a mesh send
  tool, `mesh-hydrate`, or the bundled script.
- If a mesh send tool/API exists, call it with recipient labels and body text.
- If the `mesh-hydrate` command is available, run it with recipient labels and send its exact output.
- If only the bundled script is available, run it from the skill installation directory, not from the conversation cwd.
- Keep routing out of the body text; the body is only the human-readable message.
- When recipients are present, the sent message must include the `cc-mesh:` trigger generated by the tool/script.
- Before sending, verify the final text contains both `cc-mesh:` and at least
  one Discord mention such as `<@111111111111111111>`.
- If hydration fails because a label is unknown or no participant config exists,
  do not send a routed reply. Report the missing label/config in plain language.

Recipient labels are local names configured outside the skill, such as `alice`, `reviewer`, or `ops-bot`. Use only labels present in the local participant config.

If you receive:

```text
cc-mesh: alice
<@Alice> Ask one yes/no question.
```

And you are `alice`, a normal reply to the sender should be hydrated to the sender's local label, unless you deliberately choose different or additional recipients.

Hydrate example:

```bash
mesh-hydrate --to facilitator --body "Is it commonly found in a home?"
```

Manual fallback checklist:

1. Pick recipient labels from the local participant config.
2. Run `mesh-hydrate --to label1,label2 --body "message body"`.
3. Send the exact output from the command/script.
4. If the output has no Discord mention, stop and fix config before sending.

Bundled-script fallback:

```bash
node /path/to/mesh-discord-routing/scripts/mesh-hydrate.mjs --to facilitator --body "Is it commonly found in a home?"
```

Do not run `node scripts/mesh-hydrate.mjs` unless your current working directory is the skill directory.

The command/script outputs the Discord-ready message with `cc-mesh:` and mentions already composed. It requires a local config file such as `participants.local.json` or the `MESH_PARTICIPANTS_JSON` environment variable.
